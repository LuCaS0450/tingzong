## 日常开发

1. 查看当前分支和已有改动，不把其他任务的未完成改动混入当前提交。
2. 小型修改可在 `main` 完成；较大功能使用 `feature/<主题>` 临时分支。
3. 完成一批相关修改后，按实际风险做最少且充分的验证。失败或未完成的内容不作为稳定结果合并。
4. 核对公开暂存区并运行 `python scripts/check_public_repository.py`。本机 hooks 也会在提交和推送时检查。
5. 提交公开修改，再运行 `python scripts/sync_private_materials.py --message "本批素材变更说明"`。有变更时创建独立素材提交，并记录对应公开 commit。
6. 自动将已完成的公开提交推送到对应 GitHub 分支。较大功能验证后合并到 `main` 并推送，是否清理功能分支按实际需要决定。

上述自动提交和推送已获用户明确授权，无需每批重新询问；公开范围扩大、源码授权变更或新增对外发布仍是不同决定。这是开发工作约定，不是监视任意文件变化的后台上传程序。

检查读取暂存区或待推送 commit 的真实 blob，问题只输出文件、行号和类别，不回显疑似密钥。检查覆盖路径边界、未批准媒体、常见凭据格式及提交邮箱；不能替代新增资源的来源和许可核对。不要绕过 hooks 或强制把非公开文件加入公开仓库。

## 本机素材仓库

位置：`.private/materials.git`。保存独立 Git 元数据，与公开仓库共用工程中的原文件，不另建素材工作副本。仅通过专用脚本或明确指定 `--git-dir`、`--work-tree` 的命令操作。

纳入 `content/`、未公开的历史 `docs/` 和 `scripts/`、`app/src/` 中未公开的素材，以及根目录研究脚本和资料文件。已进入公开暂存区的文件不会重复加入素材当前版本。新文件按这些目录边界纳入，敏感路径和疑似凭据会被拒绝。缓存、构建输出、日志、签名、服务配置、个人账号记录及 `.private/` 下的备份不进入素材仓库。

```powershell
# 没有变更时不创建空提交。
python scripts/sync_private_materials.py --message "更新设计与研究资料"

# 查看素材历史，不更改原文件。
git --git-dir=.private/materials.git --work-tree=. log --oneline -8
```

素材仓库设置 `push.default=nothing`，不配置 remote，并安装拒绝推送的 hook。脚本发现已配置远程就会停止。它仅在本机保存历史，不是异地备份，不能通过公开仓库克隆恢复。

素材 commit 的 `Public-Commit` 对应公开版本。恢复时按目标 commit 选择具体文件；两个仓库操作同一份原文件，不应无差别切换整棵素材工作树。初始化之前的旧版本不能由本次基线凭空恢复。
